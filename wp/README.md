# wp

WebPをJPEGへ変換します。対象は単一ファイルまたはディレクトリ直下のWebPです。

```
wp.exe image.webp
wp.exe C:\images
```

- JPEG品質75、色差サブサンプリング4:2:0。libjpeg-turboを使用します。stb版と画素・ファイルサイズは一致しません。
- 変換成功後、元WebPを削除します。透過情報は保持しません。
- 既存JPEGや出力名の重複があれば、一括処理の開始前に終了します。
- 一時ファイルへの書き込み・フラッシュ・closeと正式名への移動が成功してから元WebPを削除します。
- 個別の変換失敗は報告して後続を処理し、1件でも失敗すると終了コード1を返します。
- `imgi_1_1.webp`は`img001.jpeg`へ、それ以外は拡張子を`.jpeg`へ変更します。

ビルドはVisual Studioのx64 Native Tools環境で、同梱のx64静的ライブラリを使用してください。古いNuGet画像ライブラリへの依存はありません。Debugも同梱ライブラリに合わせてrelease static CRTを使用します。

```
msbuild wp\wp.vcxproj /p:Configuration=Release /p:Platform=x64
powershell -File wp\test-wp.ps1 -Exe x64\Release\wp.exe
```

テストは一時ディレクトリに作ったコピーのみを処理します。Unicode・長い数字、既存出力、出力名重複、壊れた入力を含むバッチ、ロックされた入力を確認します。

## 検証記録

2026-10-09、MSVC 14.51、x64、`/O2 /MT /std:c++20`、デバッグ情報なしの直接ビルドで回帰テスト5ケースとJPEG再デコードに成功しました。当時の通常のMSBuild検証は実行環境の`MSPDB140.DLL`不一致（LNK1101）で失敗しています。PDB生成の無効化はプロジェクトの既定値には反映していません。

旧版は変更前の`wp.cpp`を同じ最適化条件でビルドし、両版の品質75で比較しました。ディレクトリへのコピーは計測外、プロセス起動・列挙・変換・書き込み・元ファイル削除は計測内、標準出力は破棄しています。各3回の中央値です。

| 入力 | 旧版 | 新版 |
|---|---:|---:|
| 同梱test.webp（128×128）のコピー300枚 | 0.724秒 | 1.143秒 |
| 同画像を3000×2000へ拡大しWebP再圧縮したコピー15枚 | 1.480秒 | 0.678秒 |

大画像で約2.2倍の速度、小画像では約58%の時間増加でした。新しい処理には一時ファイルとディスクへのフラッシュによる安全性向上も含まれ、エンコーダだけの比較ではありません。同じ画像のコピーによる限定的な計測であり、実際の画像集合・ストレージでは結果が変わります。並列化は未導入です。

## 同梱ライブラリの配置

libwebpはルートの`packages/libwebp-1.6.0-windows-x64`、libjpeg-turboは`packages/libjpeg-turbo64`を参照します。ビルド用ヘッダ・静的ライブラリと検証用ツールを含みます。これら2フォルダはGitに含め、NuGetの旧パッケージキャッシュは使用しません。
## ソリューション内の配置（2026-10-09）

ここに記載したビルド・テストコマンドは、リポジトリのルートで実行します。Visual Studio経由のx64ビルドは、ルートの`x64/Release`または`x64/Debug`へ実行ファイルを出力します。中間ファイルは各プロジェクトの`out/obj/<Platform>/<Configuration>`に置きます。生成物と`*.vcxproj.user`などの個人設定はGit対象外です。

過去の検証・速度比較は記載した環境での記録です。今回のREADME更新に伴う再計測は行っていません。
