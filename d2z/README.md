# d2z — フォルダのZIP圧縮

bit7z 4.1.0を通じて`7z.dll`を直接使用します。`7z.exe`は起動せず、DLLを一括処理につき1回だけ読み込みます。

```powershell
d2z.exe "C:\Images" "C:\Documents"
d2z.exe --fast "C:\Images"
d2z.exe --store "C:\Videos"
d2z.exe --dll "D:\Tools\7-Zip\7z.dll" "C:\Images"
d2z.exe -- -folder
```

## 進捗と圧縮モード

各フォルダの処理前に、件数と対象パスを即時表示します。圧縮中はDLLが報告する処理量から割合を計算し、10%単位で表示します。小さな入力では途中の割合を飛ばす場合があります。100%は圧縮処理の進捗で、ZIPの書き込み・確定が完了すると`Created:`を表示します。

```text
[1/3] Compressing: C:\Images
  Compressing: 10%
  Compressing: 100%
Created: C:\Images.zip
```

- 通常実行は標準圧縮です。`--fast`は高速圧縮、`--store`は無圧縮ZIPです。
- モードは一括処理全体に適用します。同時・重複指定はエラーです。
- `--`以降はすべてフォルダ名として扱います。

## パスと安全性

- `images`、末尾区切り付きのパス、絶対パスはいずれも隣の`images.zip`へ出力します。`images.v1`の出力は`images.v1.zip`です。ドライブのルートは受け付けません。
- ZIP内のパスは圧縮対象からの相対パスです。作業ディレクトリは変更しません。
- 入力直下に項目が1つだけあり、それがフォルダなら、その中身を圧縮します。
- 既存ZIPは更新・上書きしません。圧縮中に同名の出力が作成された場合も上書きしません。
- 入力と同じ親ディレクトリの専用一時フォルダにZIPを作成し、圧縮・フラッシュ・close成功後に正式名へ移動します。読み取れない入力などのエラー時は、不完全なZIPを正式名で残しません。
- 失敗時は一時フォルダを削除します。削除できなければ残ったパスを報告します。強制終了では一時フォルダが残る場合があります。
- 元フォルダは保持します。失敗後も後続入力を処理し、1件以上の失敗で終了コード1を返します。
- 空フォルダは空ZIPとして作成します。圧縮中に変更される元データのスナップショット保証はありません。

## DLLの設定

実行ファイルとDLLのアーキテクチャを合わせてください。x64版にはx64の`7z.dll`が必要です。検索順序は次のとおりです。

1. `--dll`で明示したパス
2. 実行ファイルの隣の`d2z.pref`の1行目
3. 実行ファイルの隣の`7z.dll`
4. `C:\Program Files\7-Zip\7z.dll`

`d2z.pref`はUTF-8（BOMあり・なし）とWindowsコードページに対応します。旧`7z.exe`パスは同じ場所の`7z.dll`へ読み替えます。明示したパスが存在しなければエラーです。

```text
D:\Tools\7-Zip\7z.dll
```

## ビルドとテスト

VS2026のC++デスクトップ開発、Windows SDK、CMake 3.24以上が必要です。初回はbit7zと7-Zip SDKの取得にネット接続が必要です。bit7zのバージョンと取得ファイルのSHA-256をCMakeで固定しています。

```powershell
powershell -File d2z\build.ps1 -Configuration Release -Platform x64
powershell -File d2z\test-d2z.ps1 -Exe d2z\out\build\x64\Release\d2z.exe
```

`d2z.vcxproj`は同じスクリプトを呼ぶMakefileプロジェクトで、ソリューションからビルド・リビルドできます。実行時の`7z.dll`は別途配置してください。

## 検証・速度比較（2026-10-09）

VS2026のRelease・Debug x64リビルドと、両構成の回帰テスト13ケースが成功しました。相対パス・末尾区切り・日本語名、処理開始表示、単一サブフォルダ解除、階層保持、既存ZIP保護、ロックされた入力、失敗後の継続、空ZIP、圧縮モード、旧pref移行、明示DLL指定、ドットを含むフォルダ名、不正モード、`--`を確認します。ZIP整合性検査のため、テストスクリプトは7z.exeも使用します。

直前のexe版とDLL版をMSVC 14.51のRelease相当（`/O2 /MD /std:c++20`）、7-Zip 19.00のexe/DLLで比較しました。テキスト2ファイルを含む小さなフォルダ30個を1回の起動で通常圧縮し、3回の中央値を比較しました。入力作成は計測外、起動・圧縮・進捗出力・フラッシュ・確定は計測内です。各回で全ZIPの内容一致を確認しました。

| 実装 | 中央値 |
|---|---:|
| exe版 | 1.100秒 |
| DLL版 | 0.291秒 |

この条件では約3.8倍（所要時間約74%減）でした。大容量や多数の小ファイルでは結果が異なります。

DLL版でテキスト4,600,000バイトとシード固定の疑似乱数4MiBを同じフォルダに入れ、各モードを3回比較しました。全出力ファイルのSHA-256一致を確認しています。

| モード | 中央値 | ZIPサイズ |
|---|---:|---:|
| 通常 | 169ms | 4,206,783バイト |
| --fast | 130ms | 4,206,783バイト |
| --store | 50ms | 8,794,586バイト |

この入力で高速モードは通常より約23%短縮しました。すべての入力で同じ速度・圧縮率になることは保証しません。複数フォルダの並列圧縮は導入していません。
