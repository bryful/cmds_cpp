# rh

指定ディレクトリ直下のフォルダと対応ファイルの名前を整えます。7-Zipや外部プロセスは使用しません。

```
rh.exe C:\downloads
rh.exe
```

引数を省略すると作業ディレクトリを処理します。複数引数とファイル単体の入力はエラーです。再帰処理は行いません。

## 変換内容

- フォルダ、および`.zip .rar .7z .mp4 .mov .mpg .mpeg`のファイルが対象です。拡張子の判定は大文字・小文字を区別しません。拡張子自体は保持します。
- 名前の本体をNFC正規化し、全角英数字・空白・括弧などを従来の規則で変換します。波ダッシュは全角の`～`へ統一します。
- 削除語をリスト順に適用し、連続する半角空白を1つに集約して前後の空白を除去します。
- 変換後が空、`.`、`..`、末尾ドットの場合は失敗とします。その他のWindowsで無効な名前もリネーム失敗として報告します。
- リンクやリパースポイントは対象外です。既存名としては予約し、上書きしません。

## 設定ファイル

実行ファイルと同じ場所の`rh.lst`を使用します。PATH経由で起動しても場所は変わりません。

UTF-8（BOMあり・なし）の1行につき1つの削除語を指定します。空行は無視します。空のリストは「削除語なし」です。不正なUTF-8・NUL・読み込みエラーでは、既存設定を上書きせず、リネームを開始する前に終了します。

設定がない場合は従来の既定語で作成します。設定ファイルを作成できなければ失敗を報告して終了します。

## 衝突とエラー

- 全項目の名前を最初に取得し、対象を元のファイル名のUTF-16順で処理します。連番割り当て順を固定しました。
- 同名があれば`_1`、`_2`…を拡張子の前へ付加します。既存の番号付きファイルも保護します。
- 使用中の名前と次の連番をメモリ上で管理し、毎回`_1`からファイルシステムを探索しません。
- リネームは既存宛先を置換しないWindows APIで行います。別プロセスが宛先を作った場合も衝突として再試行します。
- 大文字・小文字を区別しない保守的な名前管理を使用します。空いた最小番号の再利用は保証しません。
- 失敗時は対象パスと理由を報告し、後続の項目を処理します。変更・変更不要・失敗を集計し、1件でも失敗すると終了コード1を返します。
- 一括処理全体のロールバックは行いません。途中で失敗した場合も、先に成功したリネームは保持します。
- ログはUTF-8です。旧版のリダイレクト時のUTF-16出力から変更しています。

## ビルドとテスト

Visual Studioのx64 Native Tools環境で実行します。Unicode正規化に必要な`Normaliz.lib`をプロジェクトに明示しました。

```
msbuild rh\rh.vcxproj /p:Configuration=Release /p:Platform=x64
powershell -File rh\test-rh.ps1 -Exe x64\Release\rh.exe
```

テストはスクリプトと同じ場所に専用フォルダを作成し、実行ファイルのコピー・テスト設定・テストファイルのみを操作します。基本変換と変更不要、NFC、既存名衝突、ロック失敗後の継続、空の変換結果、不正UTF-8、PATH起動、入力種別、既定設定の9ケースを確認します。

## 検証記録（2026-10-09）

MSVC 14.51のx64直接ビルド（`/O2 /MT /W4 /std:c++20 /utf-8`）と、PDB生成を検証時だけ無効にしたRelease x64のMSBuildが成功しました。両方で回帰テスト9ケースが成功しています。プロジェクト既定のPDB設定は維持しています。

旧版と新版を同じMSVCの`/O2 /MT /std:c++20 /utf-8`でビルドし、空の削除語リストで比較しました。衝突なしは`Ａ0.zip`など、衝突ありは8文字の全角・半角Aの組み合わせを使用しています。各ファイルに異なる内容を保存し、実行後に件数と全内容が保持されることも確認しました。

入力作成と内容検証は計測外、実行ファイルの起動・列挙・変換・リネームは計測内、標準出力は破棄しています。各3回の中央値です。

| 入力 | 旧版 | 新版 |
|---|---:|---:|
| 128件・衝突なし | 0.196秒 | 0.118秒 |
| 128件・同名へ集中 | 2.824秒 | 0.105秒 |
| 256件・衝突なし | 0.356秒 | 0.216秒 |
| 256件・同名へ集中 | 10.870秒 | 0.215秒 |

256件の衝突ケースでは約50倍、衝突なしでは約1.65倍の速度でした。人工的に衝突を集中させたデータであり、実際のファイル名・ストレージ・削除語数によって効果は変わります。並列リネームは導入していません。
